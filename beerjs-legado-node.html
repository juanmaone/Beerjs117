RYAN DAHL · 2018

Siete arrepentimientos. Distintas consecuencias.

Promises · seguridad · GYP · package.json
node_modules · extensiones · index.js
Complejidad: resolución de módulos y convenciones.
Mantenimiento: build nativo y manifiestos.
Seguridad: acceso por defecto a recursos del proceso.
JSConf EU 2018 · “10 Things I Regret About Node.js” · siete decisiones, no siete vulnerabilidades.
Promises: abandonarlas complicó el modelo asíncrono. Seguridad: permisos amplios. GYP: build nativo complejo. package.json: metadatos y resolución. node_modules: estructura pesada. Extensiones e index.js: búsqueda implícita. No equiparar toda complejidad a una vulnerabilidad. DENO 1 → DENO 2

De cuestionar el ecosistema a convivir con él.

Deno 1.0 (2020): permisos explícitos, ESM y herramientas integradas.
Antes de 2.0: compatibilidad Node y npm incorporada gradualmente.
Deno 2 (2024): consolida compatibilidad con package.json, npm y proyectos existentes.
TypeScript integrado no implica typecheck al ejecutar.
No decir que npm llegó por primera vez con Deno 2: npm estable en Deno 1.28, package.json en 1.31. Deno 2 consolida el camino. deno run y deno check son pasos distintos.

DEMO 01 · SISTEMA DE ARCHIVOS

¿Puede tu aplicación leer secretos que no necesita?

Menor privilegio: Node --permission vs Deno default-deny
read-secret.mjs
import { readFileSync } from "node:fs";
console.log(readFileSync("./secret.txt", "utf8"));
Node 24 — sin flags
$ node read-secret.mjs
Lista para ejecutar
Node 26 — permisos
$ node --permission --allow-fs-read=./read-secret.mjs read-secret.mjs
Lista para ejecutar
Deno 2 — default-deny
$ deno run --no-prompt read-secret.mjs
Lista para ejecutar
Primera demo completa. Ejecutar tres. Se permite explícitamente leer solo el archivo de entrada; secret.txt queda fuera de esa autorización. El modelo de permisos no es un sandbox adversarial.

DEMO 03 · RED

El último paso de un robo es sacar el dato.

Node 24: permisos sin bloqueo de red · Node 26: --allow-net · Deno: hosts explícitos
outbound.mjs
import { argv } from "node:process";
const response = await fetch(argv[2] || "http://127.0.0.1:8765/ping");
if (!response.ok) throw new Error(`HTTP ${response.status}`);
console.log("OUTBOUND RESULT:", await response.text());
Node 24 — --permission
$ node --permission --allow-fs-read=./outbound.mjs outbound.mjs
Lista para ejecutar
Node 26 — --permission
$ node --permission --allow-fs-read=./outbound.mjs outbound.mjs
Lista para ejecutar
Deno 2 — default
$ deno run --no-prompt outbound.mjs
Lista para ejecutar
Demo de red. Node 24 vs 26 con --permission y Deno. Un proceso de laboratorio separado sirve PONG en loopback; el proceso restringido solo hace fetch. No hay tráfico externo. El arnés de laboratorio de Deno tiene permisos para preparar el servidor y lanzar el proceso; el hijo se ejecuta sin permisos. Node 26 --allow-net no restringe por host.

DEMO 05 · SUPPLY CHAIN

Preinstall / postinstall: comodidad que también ejecuta código.

npm 11 por defecto ejecuta · npm 12 bloquea scripts no aprobados · Deno bloquea por defecto
demos/demo-hook/package.json
{"name":"demo-hook","version":"1.0.0","scripts":{
  "preinstall":"node preinstall.cjs",
  "postinstall":"node postinstall.cjs"
}}
npm 11
$ npm install --no-audit --no-fund --foreground-scripts
Lista para ejecutar
npm 12
$ npm install --no-audit --no-fund --foreground-scripts
Lista para ejecutar
Deno 2
$ deno install --node-modules-dir=auto
Lista para ejecutar
Demo estrella: paquete empaquetado durante docker build, servido por un registro en loopback dentro del contenedor. Comparar npm 11 y 12. INSTALL_EXIT debe ser 0 antes de interpretar los marcadores. Los fallos de preparación, instalación o evidencia se muestran. El arnés de Deno tiene permisos para preparar el laboratorio; deno install conserva su política de scripts sin --allow-scripts. No son scripts del proyecto raíz.
NO ES SOLO BLOQUEAR

Qué podés aplicar mañana en un repositorio real

npm 12 · strict-allow-scripts=true · min-release-age=7 · npm ci · revisión de scripts
Son configuraciones de npm. strict-allow-scripts=true convierte scripts sin aprobar en error de instalación; aprobar solo lo revisado con allowScripts. min-release-age=7 puede retrasar parches: usar excepciones deliberadas. npm ci requiere lockfile; no se demuestra con el fixture recién creado.
DEMO 06 · TYPESCRIPT

Ejecutar un .ts no significa verificar sus tipos.

Node borra tipos; tsc --noEmit verifica · Deno run vs deno check
typecheck.ts
function upper(s: string) { return s.toUpperCase() }
console.log(upper(42));
Node 24
$ node typecheck.ts
Lista para ejecutar
Node 26
$ node typecheck.ts
Lista para ejecutar
Deno 2
$ deno check --no-remote typecheck.ts
Lista para ejecutar
Explicar ejecución TS versus verificación: node app.ts puede ejecutar y fallar en runtime; deno check detecta tipos; en Node tsc --noEmit en CI.
NODE 24 / NODE 26

Qué viene por defecto y qué tenés que activar

Permisos: opt-in · TS stripping: integrado · Red: Node 25+ opt-in · Auditoría: 25.8+
Node 24 LTS → --permission (opt-in) · .ts sin typecheck
Node 26 Current → --permission-audit (opt-in), --allow-net (opt-in)
npm 12 → política de aprobación de lifecycle scripts (no depende de Node 26)
Tabla final de estado: flags opt-in, capacidades experimentales y npm desacoplado de Node. Pedir que prueben node -v y npm -v.
APLICACIÓN

Reducí lo que un proceso puede hacer.

Usar versiones soportadas y permisos mínimos.
Entregar solo los secretos que necesita cada proceso.
Validar entradas, rutas, argumentos y destinos de red.
Aislar código no confiable con límites del sistema operativo.
Priorizar rutas y superficies reales. No interpolar entradas en comandos de shell. Los permisos ayudan ante errores; código hostil requiere una frontera de aislamiento adecuada.
DEPENDENCIAS + EQUIPO

Hacé revisable la confianza.

Revisar y aprobar scripts de instalación.
Versionar lockfiles y usar npm ci.
Actualizar con revisión y una vía rápida para parches.
CI: pruebas, typecheck, controles de dependencias y secretos.
Una política tiene responsables, excepciones y una comprobación.
Una dependencia bloqueada puede necesitar un script legítimo: revisar antes de aprobar. npm ci no elimina los lifecycle scripts por sí solo. AVISO PRIVADO: antes del cierre repetir la pregunta de confianza sobre configuración y desarrollo seguro.
